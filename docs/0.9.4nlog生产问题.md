#### 2.1.3 ND-3 深度特征分析：`void*` 参数立即解引用的"按契约非空"推定

> **背景**：ND-3 原始建议提及了 `nlog_ipc_mbuf_get_buf_data`、`nlog_*_proc` 等 nlog 项目特有的函数名。
> 厂商无法看到用户代码，不能硬编码这些函数名。以下提炼的是**不依赖项目特定知识**的通用结构特征。

##### 问题本质

在 C 语言 IPC/回调/消息处理场景中，存在一类函数：其参数为 `void*` 无类型指针，代表框架传递的消息缓冲区。
函数入口处将该参数**立即**转换为有类型指针并解引用，不做 NULL 检查——因为框架（消息队列、事件循环、RPC 分发器）
保证调到本函数时消息非空。这是一种**调用者契约（caller contract）**：调用方负责保证非空，被调方不做防御性检查。

SecGuard 当前将 `void*` 参数标注为 `maybe-null`，导致后续解引用全部成为候选。
但这个标注过于保守——当 `void*` 参数在函数体内被**无守卫地立即解引用**时，恰恰说明开发者按"非空契约"编写，
否则代码根本无法工作。

##### 三个子模式的通用结构特征

**子模式 A：accessor 转换后解引用**

```c
void callback_fn(void *mbuf)  // void* 参数
{
    // 第一条非空语句：调用 accessor 取出数据区指针
    void *raw = some_accessor(mbuf);
    T *typed = (T *)raw;
    typed->field = ...;  // 立即解引用，无 NULL 检查
}
```

**特征判据**（全部满足）：
1. 函数参数类型为 `void*` 或 `const void*`
2. 函数体内，该参数在**前 5 条非声明非空语句**内被传给另一个函数（accessor）或被 cast
3. accessor 返回值或 cast 结果在**同一区块内**被解引用（字段访问或下标）
4. 从函数入口到解引用点之间，**不存在**对该参数或中间变量的 `== NULL` / `!= NULL` 比较
5. 参数未被 `return` 语句单独返回（排除 passthrough wrapper）

> **注意**：`some_accessor` 是任何接受 `void*` 并返回 `void*`/`T*` 的函数调用——不限于特定函数名。
> 判据是"参数被传入某个函数调用，且返回值立即被解引用"，而非函数名匹配。

**子模式 B：直接 cast 后解引用**

```c
void msg_handler(void *msg)  // void* 参数
{
    T *typed = (T *)msg;     // 直接 cast
    uint32_t val = typed->field;  // 立即解引用
}
```

**特征判据**（全部满足）：
1. 函数参数类型为 `void*` 或 `const void*`
2. 函数体内，该参数在**前 3 条非声明非空语句**内被直接 cast 为有类型指针
3. cast 结果在**同一区块内**被解引用（字段访问或下标）
4. 从函数入口到 cast 之间，**不存在**对该参数的 `== NULL` / `!= NULL` 比较

**子模式 C：void\* 参数经指针算术生成同伴指针后解引用**

```c
void handler(void *buf, uint32_t len)  // void* 参数
{
    T *head = (T *)buf;
    U *body = (U *)(head + 1);   // 指针算术，head 是 buf 的 cast 结果
    body->field = ...;            // 解引用同伴指针
}
```

**特征判据**（全部满足）：
1. 函数参数类型为 `void*` 或 `const void*`
2. 存在 `T *x = (T *)param` 的直接 cast
3. 存在 `U *y = (U *)(x + N)` 或 `U *y = (U *)((char *)x + N)` 的指针算术派生
4. 派生指针 `y` 被解引用，且中间无 NULL 检查

##### 与真实缺陷的区分边界

上述推定的**排除条件**（出现以下任一情况则不适用推定，保持候选）：

| 排除条件 | 理由 |
|----------|------|
| 参数在解引用前有 `if (param == NULL)` 判断 | 有判断说明开发者认为可能为空，但判断后的分支可能遗漏 |
| 参数来自外部输入函数的返回值（如 `recv()`/`read()` 的返回），而非函数签名参数 | 外部输入可能为空 |
| 函数内对参数调用了 `free(param)` 后继续使用 | use-after-free 场景 |
| `void*` 参数在 cast 前被赋值为其他值（如 `param = other_expr`） | 参数被重赋值，原始值不再相关 |
| 函数有 `__attribute__((nonnull))` 之外的注解暗示可空 | 显式可空标注 |

##### 实现建议

1. **检测层面**：在 `nullable_source` 过滤器中增加一条规则——当变量来源是函数参数且类型为 `void*`/`const void*`，
   且该参数在函数入口到首次解引用之间满足上述子模式 A/B/C 的结构特征时，将 null certainty 从 `maybe-null`
   降级为 `non-null-by-contract`，不产生 null-deref 候选。

2. **不依赖函数名**：整个判据仅基于参数类型（`void*`）、控制流（解引用前是否有 NULL 比较）、
   数据流（cast/accessor → 解引用的距离）三个维度，不引用任何项目特定函数名或命名模式。

3. **保守边界**：如果函数体内解引用点与 cast/accessor 点之间距离超过 5 条语句（中间有复杂控制流），
   则不应用推定——远距离解引用可能跨越分支，契约保证可能失效。

### 2.6 uninit（CWE-457）— 91 条候选，1 确认，90 排除

#### 2.6.1 误报模式分类

| 模式 | 典型特征 | 数量 | 代表候选 |
|------|----------|------|----------|
| **A. 函数输出参数（out-parameter）写入** | `*out = value` — 参数是指针，函数内写入 *out，pipeline 误判为"读取未初始化" | ~25 | 输出参数类 |

#### 2.6.2 检测改进建议

| 编号 | 建议 | 优先级 | 预期消减 |
|------|------|--------|----------|
| UN-1 | **区分读取与写入**：当 `*out = value` 中 `out` 出现在赋值左侧（LHS）时，这是写入操作而非读取，不应标记为未初始化读取。当前 `definite_init` 过滤器似乎未区分读写方向 | P0 | ~25 条 |
| UN-2 | **memset_s/calloc 初始化追踪**：`memset_s(buf, size, 0, size)` 将缓冲区清零，后续使用应视为已初始化。`calloc` 分配的内存天然清零。应在 `definite_init` 过滤器中识别这些初始化模式 | P0 | ~20 条 |

### 2.7 argument-type（CWE-686）— 10 条全部排除

**排除率：100%（10/10），0 确认。**

#### 2.7.1 误报模式

全部 10 条为同一模式：**字节缓冲区到结构体指针的反序列化转换**。

```c
nlog_analyze_log((nlog_pubmsg_head_t *)buf);
nlog_tsdb_bwm_topn_set_single_ack_data(query_body, index, (nlog_bwm_report_single_ack_t *)ack_data_tmp, ack_extern);
```

`buf`/`ack_data_tmp` 是 `uint8_t*`/`char*` 类型的原始字节缓冲区，通过显式强制转换传给接受结构体指针的函数。这是 C 语言中消息反序列化/ABI 边界的标准模式，不是类型不匹配缺陷。

#### 2.7.2 检测改进建议

| 编号 | 建议 | 优先级 | 预期消减 |
|------|------|--------|----------|
| AT-1 | **识别序列化/反序列化转换模式**：当 `uint8_t*`/`char*`/`void*` 类型的缓冲区通过显式强制转换传给接受结构体指针的函数，且该缓冲区来自 `malloc`/`memcpy`/消息接收 API 时，应标注为"ABI 边界序列化转换"并排除。可通过源类型为 `void*`/`char*`/`uint8_t*` + 显式 cast + 目标类型为结构体指针来判断 | P0 | ~10 条 |

### 2.8 buffer-overflow（CWE-787）— 6 条全部排除

**排除率：100%（6/6），0 确认。**

#### 2.8.1 误报模式

| 模式 | 数量 | 说明 |
|------|------|------|
| **malloc(size+1) 后写入 size 字节** | ~4 | 缓冲区分配 `size+1` 字节，写入最多 `size` 字节，不会溢出 |
| **固定大小缓冲区 + 有界读取** | ~2 | 如 512 字节缓冲区，读取上限 256 字节 |

| 编号 | 建议 | 优先级 | 预期消减 |
|------|------|--------|----------|
| BO-1 | **malloc 大小与写入大小的精确比较**：当 `malloc(N)` 分配缓冲区后，写入操作的最大字节数 `M` 可通过常量传播确定，且 `M <= N` 时，应排除。当前 `range_oob` 过滤器似乎未将 malloc 大小与后续写入大小做精确比较 | P1 | ~4 条 |
| BO-2 | **有界读取识别**：当 `fread(buf, 1, maxRead, fp)` 的 `maxRead` 是编译期常量且小于缓冲区大小时，应排除溢出候选 | P2 | ~2 条 |

### 2.9 signed-compare（CWE-681）— 1 条排除

**排除率：100%（1/1），0 确认。**

#### 2.9.1 误报模式

`uint8_t filter_type` 与 `0` 比较（`filter_type < 0`），这是死代码防御性检查（uint8_t 恒 >= 0），但后续 `> 11` 范围检查仍有效，无安全影响。

#### 2.9.2 检测改进建议

| 编号 | 建议 | 优先级 | 预期消减 |
|------|------|--------|----------|
| SC-1 | **死代码防御性检查识别**：当无符号类型变量与 `0` 做 `< 0` 或 `>= 0` 比较时，该条件恒为假/恒为真，是死代码但非安全缺陷。应标注为"死代码"而非 signed-compare 安全问题 | P2 | ~1 条 |

### 2.10 hardcoded-secret（CWE-798）— 1 条排除

**排除率：100%（1/1），0 确认。**

`.key = "sys_name"` — 字段名 `key` 触发密钥关键词匹配，但值 `"sys_name"` 是低熵名称字符串，不是凭证。

## 3 流水线过滤器级改进建议汇总

基于上述分析，按过滤器层级归纳改进点：

### 3.1 `nullable_source` 过滤器（null-deref）

当前仅标注变量赋值行的可能空性，缺乏以下能力：

| 改进点 | 描述 |
|--------|------|
| 短路求值守卫识别 | `if (x && x->field)` 中右侧解引用应识别短路保证 |
| 循环条件守卫识别 | `for (p = head; p; p = p->next)` 的循环条件等价 `p != NULL` |
| malloc 后判空提前返回追踪 | `p = malloc(); if (p == NULL) return;` 后续路径安全 |
| 输出参数非空推定 | `void f(T *out)` 中 `*out = value` 是写入，参数恒非空 |
| 全局数组取址非空推定 | `&g_array[i]` 恒非空 |

### 3.2 `safe_function_exclude` 过滤器（resource-leak / format-string）

| 改进点 | 描述 |
|--------|------|
| 排除 mutex/rwlock 操作 | `pthread_mutex_lock` 等同步原语不是资源获取 |
| 识别队列所有权转移 API | `nlog_en_queue` 等入队 API 表示所有权转移 |
| 进程生命周期全局变量推定 | `dlopen`/`epoll_create` 赋值给全局变量时非泄漏 |
| 字面量格式串识别 | `snprintf_s(buf, size, size-1, "%s", val)` 的 `"%s"` 是字面量 |

### 3.3 `has_release` / `ownership_transfer` / `leak_proof` 过滤器（resource-leak / memory-leak）

| 改进点 | 描述 |
|--------|------|
| 跨函数释放识别 | 入队后由消费者释放、dlopen 句柄由进程退出释放 |
| 别名追踪 | `dir`/`handle`/`fd` 等变量别名在释放调用中的匹配 |

### 3.4 `definite_init` 过滤器（uninit）

| 改进点 | 描述 |
|--------|------|
| 读写方向区分 | `*out = value` 是写入，不应标记为未初始化读取 |
| memset_s/calloc 初始化识别 | 零填充后视为已初始化 |
| 宏内初始化识别 | `HTONBUF`/`NTOHBUF` 等写入型宏的初始化效果 |
| 路径全覆盖分析 | `if-else` 所有分支均赋值时汇合点已初始化 |

### 3.5 `shared_access` 过滤器（race-condition）

| 改进点 | 描述 |
|--------|------|
| 局部变量排除 | 函数局部变量不存在跨线程共享 |
| mutex 临界区识别 | lock/unlock 之间的操作受保护 |
| 单写者标志位识别 | `g_xxx_flag`/`g_xxx_state` 单线程写入模式 |
| 精确 check-then-act 模式 | 仅"先读后写同一全局变量"且无锁保护时才标记 |

### 3.6 `taint_source` 过滤器（format-string / injection / path-traversal）

| 改进点 | 描述 |
|--------|------|
| 字面量格式串直接排除 | 字符串字面量作为格式串时无污点 |
| 内部封装函数 format 参数溯源 | 追溯调用方传入的实参是否为字面量 |
| 编译期字符串表识别 | `const char *[]` 数组的索引访问视为安全 |

### 3.7 新增建议过滤器

| 过滤器名 | 适用类型 | 描述 |
|----------|----------|------|
| `short_circuit_guard` | null-deref | 识别 `&&` 短路求值中的隐式 NULL 守卫 |
| `loop_condition_guard` | null-deref, integer-overflow | 识别循环条件对循环体内操作的守卫 |
| `truncation_contract` | integer-overflow | 识别 `snprintf_s` 返回值累加器的截断写入安全契约 |
| `process_lifetime_resource` | resource-leak | 识别赋值给全局变量的进程生命周期资源 |
| `ownership_transfer_api` | resource-leak, memory-leak | 识别入队/注册等所有权转移 API |
| `out_parameter_write` | null-deref, uninit | 识别输出参数写入模式 |
| `abi_serialization_cast` | argument-type | 识别 `void*`/`char*` 到结构体指针的序列化转换 |
